# Working principles

- Add only what the current feature needs; keep modules small and browsable.
- Treat the SQLite dataset as the source of truth and derive API/UI views from it.
- Keep official legal sources beside every plain-language explanation.
- Distinguish binding law, national transposition, case law, guidance, proposals, and inclusion practice.
- Record application dates, verification dates, jurisdiction, and unresolved country variations.
- Label generated or unreviewed editorial content; never present it as legal advice.
- Never commit `.env`, credentials, local databases, caches, generated builds, or source snapshots containing restricted material.
- Use separate least-privilege credentials for deployment and data-enrichment jobs.
- Build and verify one end-to-end feature at a time.
- Keep the product accessible: semantic controls, keyboard operation, visible focus, high contrast, and responsive layouts.
- Use Conventional Commit prefixes for working milestones.
